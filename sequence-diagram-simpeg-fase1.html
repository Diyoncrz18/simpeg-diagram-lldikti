SIMPEG LLDIKTI Wilayah XVI

Sequence Diagram Fase 1

Urutan interaksi antar aktor, Laravel SIMPEG, Keycloak, database, queue, dan layanan email/notifikasi.

Sequence Utama

Sequence ini merangkum tiga skenario inti: login SSO, import data pegawai, dan pengajuan cuti sampai notifikasi.

sequenceDiagram
    autonumber
    actor User as Pengguna
    participant Browser
    participant App as SIMPEG Laravel
    participant Keycloak
    participant DB as PostgreSQL
    participant Queue as Queue Worker
    participant Mail as SMTP/Mailpit

    rect rgb(238, 247, 248)
      User->>Browser: Buka SIMPEG
      Browser->>App: GET /
      App->>App: Cek session
      alt Belum login
        App-->>Browser: Redirect ke Keycloak
        Browser->>Keycloak: Login SSO
        Keycloak-->>Browser: Authorization callback
        Browser->>App: Callback dengan token/code
        App->>Keycloak: Validasi token dan ambil profil
        Keycloak-->>App: Email, nama, Keycloak ID
        App->>DB: Cari employee berdasarkan email/Keycloak ID
        alt Pegawai ditemukan
          DB-->>App: Employee + role internal
          App->>DB: Update keycloak_id jika kosong
          App-->>Browser: Redirect dashboard sesuai role
        else Pegawai belum terdaftar
          App-->>Browser: Halaman akun belum terdaftar
        end
      else Sudah login
        App->>DB: Load role dan permission internal
        App-->>Browser: Dashboard
      end
    end

    rect rgb(255, 248, 230)
      actor Admin as Admin Kepegawaian
      Admin->>Browser: Upload daftar_pegawai.xlsx
      Browser->>App: POST /import/pegawai/preview
      App->>App: Parse sheet Pegawai dan header 16 kolom
      App->>DB: Cek referensi golongan/status dan NIP existing
      DB-->>App: Hasil validasi
      App-->>Browser: Preview, mapping, error per baris
      Admin->>Browser: Konfirmasi import valid
      Browser->>App: POST /import/pegawai/execute
      App->>Queue: Dispatch ImportEmployeesJob
      Queue->>DB: Insert employees dan profil_status belum_lengkap
      Queue->>DB: Simpan audit log import
      Queue-->>App: Progress dan hasil import
      App-->>Browser: Laporan berhasil/gagal/skip
    end

    rect rgb(241, 245, 249)
      actor Pegawai
      actor Atasan as Atasan Langsung
      actor Kabag as Kabag/Verifikator
      actor Pimpinan as Pimpinan/PYBMC

      Pegawai->>Browser: Submit pengajuan cuti
      Browser->>App: POST /cuti
      App->>DB: Validasi saldo, hari kerja, jenis cuti, atasan
      App->>DB: Simpan leave_requests status menunggu atasan
      App->>DB: Catat audit log pengajuan
      App->>Queue: Kirim notifikasi ke Atasan
      Queue->>Mail: Email/notifikasi jika channel aktif

      Atasan->>Browser: Setujui/tunda stage 1
      Browser->>App: POST /cuti/{id}/approve
      App->>DB: Simpan approval stage 1
      App->>App: Tentukan stage berikutnya dan skip jika approver sama
      App->>Queue: Notifikasi ke Kabag atau stage berikutnya

      Kabag->>Browser: Setujui/tunda stage 2
      Browser->>App: POST /cuti/{id}/approve
      App->>DB: Simpan approval stage 2
      App->>Queue: Notifikasi ke Pimpinan

      Pimpinan->>Browser: Keputusan final
      Browser->>App: POST /cuti/{id}/finalize
      App->>DB: Update status cuti dan saldo jika disetujui
      App->>DB: Catat audit log approval
      App->>Queue: Notifikasi hasil ke Pegawai
    end
Role dan permission selalu dibaca dari database SIMPEG, bukan dari role Keycloak.
