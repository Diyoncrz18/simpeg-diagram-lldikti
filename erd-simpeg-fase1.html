Dasar Penyusunan ERD

Struktur database awal mengikuti data model pada PRD, detail migration pada issues, dan acceptance criteria pada user stories. Hasil meeting terbaru menegaskan bahwa Keycloak hanya dipakai untuk autentikasi, sedangkan role dan permission dikelola di aplikasi.

Identitas Login employees.keycloak_id menjadi penghubung akun SSO dengan data pegawai.
RBAC Internal Tabel roles, permissions, dan pivot disiapkan karena permission dikelola aplikasi.
Riwayat Append-only Pangkat, jabatan, KGB, disiplin, pendidikan, dokumen, dan pengangkatan dipisah dari tabel pegawai.
BUP Berdasarkan hasil meeting, usia pensiun paling aman diletakkan di referensi jabatan/jenis jabatan.

Mapping Sample Excel ke Database

File sample daftar_pegawai.xlsx berisi 10 baris data dan 16 kolom. Kolom tersebut cukup untuk import awal, tetapi belum mencakup semua field lengkap PRD seperti NIK, No KK, alamat, tempat lahir, data keluarga, SK, TMT pangkat, TMT jabatan, dan TMT KGB.

Catatan Implementasi Awal

  • employees menjadi pusat data pegawai sekaligus identitas aplikasi yang dihubungkan ke Keycloak melalui keycloak_id atau email.
  • RBAC internal menjadi acuan otorisasi. Fase awal dapat memakai employees.role_id atau tabel pivot employee_roles, tetapi permission tetap dibaca dari database SIMPEG.
  • Riwayat pangkat, jabatan, dan KGB harus append-only dan memakai is_latest untuk record terbaru.
  • Approval cuti awal dapat memakai approval_configs; jika nanti dinamis per pegawai, bisa diperluas dengan chain yang mengacu ke supervisor_assignments.
  • Sample Excel belum memuat semua data wajib PRD, jadi import awal perlu mendukung data parsial dan validasi field kosong.
  • BUP mengikuti PRD v1.1: maks_usia_pensiun pada referensi jabatan, dengan ref_bup sebagai tabel detail bila jenis jabatan perlu lebih spesifik.
